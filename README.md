ปล. ไม่มีความรู้หรือเคยใช้งาน Bot เลยครับ แต่พอเข้าใจการทำงานอยู่เพราะฉะนั้นขออนุญาตอธิบายตามที่เข้าใจนะครับ จากที่เรียนเกี่ยวกับ Manchine Learning

1. Bot จ่ายเงินไม่ทำงาน เช่น bot ล่ม, cookie หมดอายุ หรือ timeout ทำให้ออเดอร์ค้าง
-ตรวจสอบระยะเวลาที่ Order อยู่ใน STATE ไหนที่กำหนดไว้ PROCESSING หากเกินเวลาที่กำหนด เช่น 5 นาที ให้ถือว่า Bot อาจมีปัญหา จากนั้นเปลี่ยน STATE กลับเป็น QUEUED เพื่อให้สามารถนำไปประมวลผลใหม่ได้

2. Bot สองตัวแย่งออเดอร์เดียวกัน ทำให้จ่ายซ้ำ
-ก่อนที่ Bot จะรับ Order ให้ตรวจสอบว่า Order ยังอยู่ใน STATE QUEUED หรือไม่ หากใช่ ให้เปลี่ยน STATE เป็น PROCESSING ทันที เพื่อระบุว่า Order นี้กำลังถูก Bot ประมวลผลอยู่ หาก Bot ตัวอื่นพบว่าเป็น STATE PROCESSING แล้ว จะไม่รับ Order นี้ไปทำซ้ำ

3. Webhook ธนาคารมาซ้ำ หรือมาช้า / ผิดลำดับ
-บันทึก transaction_id ของ Webhook ที่เคยประมวลผล และกำหนดให้ transaction_id เป็น UNIQUE หากได้รับ Webhook ที่มี transaction_id เดิม ระบบจะตรวจพบว่าเคยประมวลผลแล้วและไม่ดำเนินการซ้ำ วิธีการแก้ไขผิดลำดับคือตรวจสอบ STATE ปัจจุบันและเก็บ Event time/Sequence ก่อนเปลี่ยน STATE
วิธีการแก้ไขมาช้าคือ เก็บ event_time และลำดับ Event แล้วไม่ให้ Event เก่าย้อน STATE

4. เติมไม่สำเร็จ เช่น UID ผิดหรือ provider ล่ม
-แยกประเภทของ Error ก่อนว่าเป็น Error ที่สามารถลองใหม่ได้หรือไม่ หากเป็นปัญหาชั่วคราว เช่น Timeout หรือ Provider ไม่ตอบสนอง ให้ Retry 2–3 ครั้ง แต่หากเป็นปัญหาที่ไม่สามารถแก้ด้วยการ Retry เช่น UID ผิด ให้เปลี่ยนเป็น FAILED และบันทึกสาเหตุ

5. ออเดอร์ค้าง / หมดอายุ เช่น คิวนานเกิน SLA หรือ QR หมดเวลา
-ให้มี Background Job/Scheduler ตรวจสอบ Order ที่เกินเวลาที่กำหนดเป็นระยะ ๆ หากเกินเวลาของแต่ละสถานะ ให้เปลี่ยนเป็น EXPIRED หรือสร้าง Alert เพื่อแจ้ง Admin
